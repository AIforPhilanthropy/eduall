EduAll Foundation — Grant Call 2026¶

Group Project Report: LLM Workflow (Human-AI condition)¶

Protocol: protocols/humanAI_LLMworkflow.pdf — a multi-step pipeline in which an LLM performs a sequence of distinct sub-tasks rather than a single judging call. Group: Group LLM-1, four students (A, B, C, D). Input data: data/EduAll_500_Applications_Dataset.csv (structured facts) and the 500 natural-text application files in data/individual_applications/ (the narrative evidence). Model: Google Gemini (gemini-3.5-flash-lite, temperature 0, JSON output with a schema), called from this notebook.

Our design principle is arithmetic in code, judgement in the LLM. Code does what must be exact and reproducible: the budget arithmetic, the gate, the weighted score, retrieving the peers and the allocation. The LLM does what needs reading: eligibility evidence hidden in the narrative, scoring need and merit from the documents, and drafting a recommendation with a rationale. Every LLM step reads the full application document together with the CSV row, and it enriches the CSV with new columns extracted from the text (for example whether support ends in 2027/28, or whether the document contradicts the CSV).

This notebook is our project report. It follows the protocol's four steps:

  1. Anchor the workflow's steps: every step maps to a citable requirement of the call.
  2. Design the step sequence: five steps, the code/LLM split, and where the human checkpoint sits.
  3. Build and run: every applicant goes through every step, and every step's output is logged (workflow_log.jsonl).
  4. Documentation and reproducibility: prompts and settings published, a 16% re-run with per-step agreement, and the human checkpoint stated.

Each step also has a 🧩 In AnythingLLM box. It explains how to build the same step without code, as an AnythingLLM Agent Flow (the protocol's no-code option). At the end, the notebook writes an importable flow skeleton, anythingllm_flow_eduall.json.

About the first run shipped with this notebook. The results, CSV exports and HTML of the first execution were produced with Claude (Opus 5.5) acting as the LLM endpoint: it read each prompt below and returned the JSON the schema asks for, exactly as Gemini would. Those responses are stored in llm_responses_firstrun.jsonl, keyed by applicant, step and a hash of the exact prompt. Without an API key the notebook replays them, so you can study the whole pipeline at no cost. With a GEMINI_API_KEY secret it calls Gemini live. That is the run your group reports. If you change any prompt or rule, replay stops for the changed steps, and you must run live.

Step 2 — Design the step sequence¶

Budget: ~24.4h for a 4-student group.

            ┌──────────────┐   ┌──────────────────┐   ┌───────────┐   ┌──────────────────┐   ┌───────────┐   ┌──────────────────┐   ┌────────────┐
 CSV row ──►│ 1 Intake     │──►│ 2 Eligibility    │──►│  HUMAN    │──►│ 3 Need/merit     │──►│ 4 Peers   │──►│ 5 Recommendation │──►│ Allocation │
 document ─►│ (code)       │   │ (LLM) + gate     │   │ CHECKPOINT│   │ read-out (LLM)   │   │ (code)    │   │ (LLM)            │   │ (code)     │
            └──────────────┘   └──────────────────┘   └───────────┘   └──────────────────┘   └───────────┘   └──────────────────┘   └────────────┘
                                  │ fail → out, reason logged            │ + 7 new CSV columns

Design decisions:

  • Three separate LLM sub-tasks, not one judging call. Each has its own prompt, its own JSON schema, and its own log entry. A divergence can then be traced to the step where it started (Step 4 of the protocol asks for exactly this).
  • Structured output. Each LLM call must return JSON that matches a schema, with an evidence field and a source (csv, document, both) for every verdict. The output can be checked and can go straight into CSV columns.
  • The gate is code. The LLM gives verdicts. A fixed rule turns them into eligible / conditional / human checkpoint / ineligible. The LLM can say "flag" but cannot decide a flagged case.
  • Human checkpoint between steps 2 and 3. Every applicant with a flag verdict is read in full by two of us before anything else happens.
  • Peers are retrieved by code. The dataset has no funding history, so "comparable past decisions" becomes the 4 most similar eligible applicants in the same cohort (same GNI tier and same study level, closest shortfall ratio). They reach the LLM in step 5 as calibration context.
  • Everything is logged. One line per applicant and step in workflow_log.jsonl: time, step, prompt hash, producer and the full output.

3.0 The LLM call¶

One function, llm_json, makes every LLM call. It sends the system instruction and the step's prompt, requires JSON that matches the step's schema, and retries on rate limits. It caches each response under run | step | applicant together with a hash of the exact prompt. A stopped run therefore continues where it stopped, and a changed prompt is never answered from an old response.

OUT = pathlib.Path(".")
CACHE_FILE, FIRSTRUN_FILE, LOG_FILE = OUT / "llm_responses.jsonl", OUT / "llm_responses_firstrun.jsonl", OUT / "workflow_log.jsonl"

def _load(path):
    d = {}
    if path.exists():
        for line in path.read_text(encoding="utf-8").splitlines():
            if line.strip():
                r = json.loads(line); d[r["key"]] = r
    return d
CACHE = _load(CACHE_FILE) if BACKEND == "gemini" else _load(FIRSTRUN_FILE)
print(f"responses available in cache: {len(CACHE)}")

def prompt_hash(system, user, schema):
    return hashlib.sha256((system + "\n" + user + "\n" + json.dumps(schema, sort_keys=True)).encode()).hexdigest()[:16]

class QuotaExhausted(Exception):
    pass

_client, _last_call = None, [0.0]
def _gemini(system, user, schema):
    global _client
    from google import genai
    from google.genai import types
    if _client is None:
        _client = genai.Client(api_key=GEMINI_API_KEY)
    cfg = dict(system_instruction=system, temperature=TEMPERATURE, seed=SEED, max_output_tokens=MAX_OUTPUT_TOKENS,
               response_mime_type="application/json")
    try:
        config = types.GenerateContentConfig(**cfg, response_json_schema=schema)
    except Exception:                                      # older google-genai versions (no response_json_schema)
        config = types.GenerateContentConfig(**cfg, response_schema=schema)
    for attempt in range(6):
        wait = 60.0 / REQUESTS_PER_MINUTE - (time.time() - _last_call[0])
        if wait > 0: time.sleep(wait)
        _last_call[0] = time.time()
        try:
            r = _client.models.generate_content(model=MODEL, contents=user, config=config)
            return json.loads(r.text)
        except json.JSONDecodeError:
            continue                                       # malformed JSON: ask again
        except Exception as e:
            msg = str(e)
            if "per day" in msg.lower() or "PerDay" in msg:
                raise QuotaExhausted("Daily quota reached. Re-run this cell tomorrow: cached steps are not repeated.")
            if "429" in msg or "RESOURCE_EXHAUSTED" in msg or "503" in msg:
                time.sleep(20 * (attempt + 1)); continue
            raise
    raise RuntimeError("Gemini did not return valid JSON after 6 attempts")

def llm_json(step, sid, system, user, schema, run=None):
    """One LLM sub-task for one applicant. Returns the parsed JSON response and logs it."""
    run = run or RUN_TAG
    key, h = f"{run}|{step}|{sid}", prompt_hash(system, user, schema)
    hit = CACHE.get(key)
    if hit and hit["prompt_hash"] == h:
        resp, producer = hit["response"], hit.get("producer", MODEL)
    elif BACKEND == "replay":
        raise RuntimeError(f"{key}: no stored response for this exact prompt. The prompts were changed, "
                           "so add a GEMINI_API_KEY secret and run live.")
    else:
        resp, producer = _gemini(system, user, schema), MODEL
        rec = {"key": key, "prompt_hash": h, "producer": producer, "response": resp}
        CACHE[key] = rec
        with CACHE_FILE.open("a", encoding="utf-8") as f: f.write(json.dumps(rec, ensure_ascii=False) + "\n")
    with LOG_FILE.open("a", encoding="utf-8") as f:
        f.write(json.dumps({"time": datetime.now(timezone.utc).isoformat(timespec="seconds"), "run": run, "step": step,
                            "student_id": sid, "prompt_hash": h, "producer": producer, "output": resp}, ensure_ascii=False) + "\n")
    return resp

def run_step(step, ids, build, schema, run=None, label=""):
    """Run one step over many applicants; stops cleanly (keeping everything done so far) if the quota ends."""
    out = {}
    try:
        for i, sid in enumerate(ids, 1):
            system, user = build(sid)
            out[sid] = llm_json(step, sid, system, user, schema, run)
            if i % 50 == 0: print(f"  {label or step}: {i}/{len(ids)}")
    except QuotaExhausted as e:
        print(f"STOPPED after {len(out)} of {len(ids)} applicants: {e}")
    return out
LOG_FILE.unlink(missing_ok=True)       # a fresh per-step log for this execution

  • the CSV row,
  • figures derived in code: need_2027 (expected monthly shortfall in 2027/28), shortfall_ratio, months_in_grant (months of study inside Sep 2027 – Aug 2028, from the completion date written in the file), months_to_completion and progress,

def completion(text):
    m = re.search(r"\*\*Expected Completion:\*\*\s*(January|July) (\d{4})", text)
    return (int(m.group(2)), MONTH[m.group(1)]) if m else (None, None)
df["completion_year"], df["completion_month"] = zip(*[completion(raw_docs[s]) for s in df.student_id])
def months_in_grant(y, m):                      # months of study within Sep 2027 - Aug 2028
    if y is None: return 12
    if (y, m) < (2027, 9): return 0
    if (y, m) >= (2028, 8): return 12
    return (y - 2027) * 12 + m - 9 + 1
df["months_in_grant"] = [months_in_grant(y, m) for y, m in zip(df.completion_year, df.completion_month)]

3.6 Pipeline step 5 — Recommendation drafting (LLM sub-task 3 of 3)¶

The model starts from the weighted score. It may adjust the score by at most ±1.0, and only when the step-3 scores look inconsistent with the peers' scores. It then assigns a category from fixed thresholds and writes a rationale of at most 70 words for the selection committee. It may move a case one category for a decisive documented reason the scores miss, and it must say why.

3.7 From recommendations to awards (code)¶

Our allocation rule:

  • Request: the 2027/28 shortfall over the months of study in the grant period, minus other scholarships (unless stated to end) and minus savings above a CHF 3,000 reserve, capped at the call's level maximum.
  • Award: a share of the request by category (strong_fund 85%, fund 65%, reserve 50%).
  • Order: awards are made category by category, best calibrated score first, until CHF 500,000 is spent. Awards under CHF 1,000 are not made.

# --- From recommendations to awards (our rule, code) -------------------------------------
BUDGET, MIN_AWARD, RESERVE_SAVINGS = 500_000, 1_000, 3_000
SHARE = {"strong_fund": 0.85, "fund": 0.65, "reserve": 0.50}      # share of the documented request we award
TIER = {"strong_fund": 0, "fund": 1, "reserve": 2}
# request = grant-period shortfall - other scholarships (unless stated to end) - savings above a CHF 3,000 reserve,
# spread over the months until graduation; capped at the level maximum, pro-rated to the months of study.
sch = np.where(df.support_ending.fillna(False).astype(bool), 0, df.external_scholarship_amount_chf * df.months_in_grant / 12)
sav = (df.savings_chf - RESERVE_SAVINGS).clip(lower=0) * np.minimum(1, df.months_in_grant / df.months_to_completion)
df["request"] = np.minimum((df.need_2027 * df.months_in_grant - sch - sav).clip(lower=0),
                           df.study_level.map(CAP) * df.months_in_grant / 12).round()

def allocate(d, eligible):
    """Tiers in order (strong_fund, fund, reserve), best calibrated score first, until the budget is used."""
    pool = d.loc[eligible]
    pool = pool[pool.recommendation.isin(SHARE)].assign(tier=lambda x: x.recommendation.map(TIER))
    order = pool.sort_values(["tier", "calibrated_score"], ascending=[True, False]).index
    award, left = pd.Series(0.0, index=d.index), BUDGET
    for sid in order:
        amt = float(np.floor(d.at[sid, "request"] * SHARE[d.at[sid, "recommendation"]]))
        if amt < MIN_AWARD: continue
        give = min(amt, left)
        if give < MIN_AWARD: break
        award[sid] = give; left -= give
    return award, pd.Series(range(1, len(order) + 1), index=order)

4.2 Re-run of a 16% sample¶

80 applicants are drawn at random with seed 2026 and sent through steps 2, 3 and 5 a second time, with identical inputs and settings (run2). Steps 3 and 5 are re-run for the sample members who were eligible in run 1. That way each step's agreement is measured on the same applicants and is not mixed with an earlier step's divergence. The final agreement puts run 2's decisions into the pool and spends the budget again with the same rule.

4.3 Human checkpoints in the pipeline¶

  1. Between steps 2 and 3: every applicant flagged by the eligibility step is read in full by two of us. The decisions are recorded in HUMAN_DECISIONS_FIRST_RUN and in the column checkpoint_decision.
  2. On the conditions: awards to applicants with a pending permit or a GPA below 2.5 are conditional. They are paid only after the permit is granted, or the improvement plan is confirmed, at the interview stage.
  3. On the final list: we sign off the allocation and look at the cases near the budget cut-off.

4.6 Summary of our decision path¶

  1. 500 applications → 379 eligible after the LLM eligibility step and our checkpoint, 31 of them with a condition. 121 are ineligible: 117 fail at least one criterion (standing 63, need 61, Permit C with significant resources 19, some failing more than one), and 4 are excluded at the checkpoint.
  2. Read-out: S1–S5 with evidence, plus 7 new columns from the documents. The text changes the picture for many applicants: 115 need increases and 52 major CSV/document discrepancies.
  3. Peers: 9 cohorts (GNI tier × study level), 4 peers each.
  4. Recommendations: 190 strong_fund, 81 fund, 67 reserve, 41 do_not_fund (52 scores adjusted, 12 category moves).
  5. Allocation: 103 awards, CHF 500,000. All go to strong_fund applicants, and 87 of them are from low-income countries.
